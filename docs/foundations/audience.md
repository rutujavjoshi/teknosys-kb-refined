# Audience & User Intent

One of the most common mistakes in documentation is this:

We write what we know instead of what users need.

Good documentation starts with clarity about the audience—and more importantly, their intent.

---

## Why this matters

- Prevents over-explaining or under-explaining  
- Improves usability immediately  
- Helps structure content correctly  
- Reduces user frustration  

---

## The core idea

Every user comes to documentation with a goal.


User → Intent → Content → Outcome


If your content doesn’t support that intent, it won’t be used.

---

## Understanding your audience

Your audience is rarely “everyone.”

Typical categories:
- End users → task-focused  
- Developers → integration-focused  
- Internal teams → process-focused  

Each group expects different:
- Depth  
- Terminology  
- Structure  

---

## Understanding user intent

Users typically want to:

- Complete a task  
- Fix a problem  
- Understand something quickly  

They are not here to read—they are here to move forward.

---

## Mapping audience to intent

| Audience        | Intent              | Content type        |
|----------------|-------------------|--------------------|
| New user        | Learn              | Tutorial           |
| Regular user    | Complete task      | How-to guide       |
| Developer       | Integrate system   | API reference      |
| Stakeholder     | Understand system  | Conceptual content |

---

## Common mistakes

- Writing for everyone  
- Assuming prior knowledge  
- Mixing multiple intents in one page  
- Explaining instead of enabling  

---

## Practical guidance

- Start every page by asking: *Who is this for?*  
- Then ask: *What are they trying to do?*  
- Remove anything that doesn’t support that goal  
- Test content by asking: “Can a user complete the task?”
