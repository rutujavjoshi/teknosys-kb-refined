# Task-Based Writing

Most users don’t come to documentation to read.

They come to **get something done**.

Task-based writing focuses on helping users complete a specific goal with minimum friction.

---

## Why this matters

- Improves usability immediately  
- Reduces support queries  
- Makes documentation actionable  
- Aligns content with real user behavior  

---

## The core structure

Every task should follow a simple flow:


Goal → Steps → Result


If any of these are missing, the task becomes harder to follow.

---

## What good task writing looks like

Instead of this:

“Password management is handled through the security settings panel…”

Write this:

1. Go to **Settings**  
2. Select **Security**  
3. Click **Change Password**  
4. Enter your new password  
5. Click **Save**

---

## Key principles

- Start with a clear goal  
- Use numbered steps  
- Keep each step actionable  
- Avoid mixing explanation inside steps  
- Show expected outcome  

---

## Common mistakes

- Mixing concepts with steps  
- Writing long paragraphs instead of steps  
- Assuming prior knowledge  
- Skipping expected results  

---

## Practical guidance

- Write one task per page (or clearly separated sections)  
- Keep steps short and consistent  
- Add notes only when necessary  
- Test: *Can someone complete this without asking questions?*
