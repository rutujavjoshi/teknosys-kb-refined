# Writing Guidelines

<span class="badge badge-beginner">Beginner</span>

## Overview
Effective technical writing is clear, structured, and user-focused. Content should be easy to scan, understand, and act upon.

---

## Core Principles

### 1. Write for the user
- Focus on what the user needs to do
- Avoid internal/system-centric language

### 2. Use topic-based structure
- One topic = one purpose
- Keep content modular and reusable

### 3. Keep it concise
- Avoid unnecessary words
- Prefer short sentences

---

## Content Types

### Concept
- Explains *what* and *why*
- Example: “What is an API?”

### Task (Procedure)
- Step-by-step instructions
- Use numbered lists

### Reference
- Structured information
- Tables, parameters, specs

---

## Example

❌ Poor:
"Users can perform configuration by navigating through multiple system interfaces..."

✅ Better:
"To configure the system:
1. Open Settings
2. Select Configuration
3. Update required fields"

---

## Checklist

- Is it clear?
- Is it concise?
- Is it actionable?
